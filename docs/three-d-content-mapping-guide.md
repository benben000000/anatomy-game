## The rule that matters

**One muscle is not one mesh.**

Three structures span multiple nodes, and in two cases the parent and its parts
coexist as separate objects:

```
Trapezius       -> Ascending / Descending / Transverse parts
                   PLUS a whole "Trapezius muscle.r" node
Deltoid         -> Acromial / Clavicular / Spinal parts
                   PLUS a whole "Deltoid muscle.r" node
Pectoralis maj. -> Abdominal / Clavicular / Sternocostal heads
                   PLUS a whole "Pectoralis major.r" node

Biceps brachii  -> Long head / Short head, NO whole-muscle node
Triceps brachii -> Long / Lateral / Medial heads, NO whole-muscle node
Gastrocnemius   -> Lateral / Medial heads, NO whole-muscle node
```

So a mapping is **many nodes to one structure**, and selection priority decides
which part wins where they overlap.

## Node naming

Terminologia Anatomica names with a laterality suffix:

```
Deltoid muscle.r
Long head of triceps brachii.r
Soleus muscle.r
```

Names are case-sensitive and exact. The suffix is recorded explicitly in
`laterality_suffix` so the credit and licence record can name a part precisely.

## Why mappings are never generated by matching

A substring search over the real node lists produces false positives.

Searching `oblique` returns only unrelated structures:

- Oblique cord or radio-ulnar syndesmosis
- Oblique ligament of 1st finger
- Oblique head of adductor pollicis

Searching `serratus` returns the muscle **and** two bursae:

- Serratus anterior muscle.r
- Infraserratus bursa.r
- Supraserratus bursa.r

Searching `deltoid` returns the muscle, three parts, and two bursae:

- Deltoid muscle.r
- Acromial / Clavicular / Spinal part of deltoid muscle.r
- Subacromial-subdeltoid bursa.r
- Subdeltoid bursa.r

Mapping those bursae to their muscles would mark a learner wrong for tapping a
bursa when asked for the muscle.

**Therefore `node_names` is an explicit allowlist, confirmed by a human against the
real node list. `auditNodesAgainstPack` exists so a stale allowlist fails loudly
rather than silently becoming unselectable.**

## Structure of a mapping

Key fields, and why each exists:

| Field | Why |
|---|---|
| `parts[]` | One structure may span many nodes |
| `is_parent_overlay` | Marks a part sitting above a parent; must not answer for it |
| `selection_priority` | Resolves overlap deterministically |
| `occlusion_policy` | `always`, `only_when_unoccluded`, or `peel` |
| `requires_disambiguation` | Structure is too small or too crowded to tap alone |
| `fair_target_radius_m` | **Measured on device. Null blocks publication.** |
| `mapping_status` | `draft` until a human has confirmed the geometry |
| `reviewer`, `review_date` | Required for publication |

### `occlusion_policy`

| Value | Meaning |
|---|---|
| `always` | Freely visible; always askable |
| `only_when_unoccluded` | Askable only when not covered |
| `peel` | Has overlay parts; selecting a part must not answer for the parent |

A mapping combining overlay parts with `occlusion_policy: 'always'` is rejected at
three independent layers: the Zod schema, the content validator, and the mapper's
default behaviour.

## Governance

A mapping can only reach `published` with all of:

1. `reviewer` — a named human
2. `review_date` — YYYY-MM-DD
3. `fair_target_radius_m` — measured on a real device
4. `content_source_references` — at least one educational source
5. The underlying structure is itself `published`

Rule 5 is enforced as `3d-mapping-ahead-of-structure`: unreviewed geometry must
never appear ahead of unreviewed content.

**No mapping can be published by machine.** The schema cannot distinguish a
human-confirmed mapping from a plausible-looking one. That is a deliberate limit,
and the `reviewer` field exists to make the human step explicit.

## Tapping fairness

| Structure | Policy | Reason |
|---|---|---|
| rectus femoris | `always` | Large, anterior, unobstructed |
| vastus lateralis | `always` | Lateral, wraps from anterior |
| tibialis anterior | `always` | Anterior shin, clear |
| gluteus maximus | `always` | Large, posterior |
| latissimus dorsi | `always` | Single node, posterior |
| serratus anterior | `requires_disambiguation` | Small area, partly hidden by scapula |
| vastus medialis | `requires_disambiguation` | Abuts rectus femoris |
| soleus | `only_when_unoccluded` | Covered by gastrocnemius posteriorly |

**Soleus is a real content finding.** It is largely covered by gastrocnemius in the
only posterior view this pack provides, so it is **not fairly askable from behind**.
It is retained as draft pending a reviewer decision, mirroring the same question
raised for the 2D board — not quietly removed to make the pack look easier.

## Deliberately unmapped

Not every node should be selectable.

| Node | Why excluded |
|---|---|
| Common tendon of biceps brachii | Tendon, not muscle |
| Common tendon of triceps brachii | Tendon |
| *n* tendon sheath | Sheath |
| Infraserratus / Supraserratus bursa | Bursa |
| Subacromial-subdeltoid bursa | Bursa |
| *n* subtendinous bursa | Bursa |
| Thoracoacromial artery Deltoid br | Artery |

A test asserts every one of these resolves to nothing.

### Structures with no 3D mapping

| Structure | Reason |
|---|---|
| frontalis | No matching node |
| sternocleidomastoid | No matching node |
| rectus_abdominis | No matching node — no trunk pack exists upstream |
| external oblique | No matching node; "oblique" matches only unrelated structures |
| erector spinae | No matching node, nor iliocostalis / longissimus / spinalis |

Five of nineteen. They are **not** quietly dropped: the 2D board remains the
complete route, and `structuresNeedingTwoDimensionalFallback` names them explicitly.

## Mapping workflow

1. Run `auditNodesAgainstPack` against the real node list
2. Read the geometry — **a node name that reads correctly may still be the wrong mesh**
3. Assign parts, priorities and an occlusion policy
4. Measure the tap radius on an iPad Air M4
5. Attach an educational source
6. Record the reviewer and date
7. Publish only when the underlying structure is published

**Step 2 is the one that cannot be automated or skipped.** Names are a proxy for
geometry, not a guarantee of it.
